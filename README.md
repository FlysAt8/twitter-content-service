# Content Service

Сервис для управления сообщениями, подписками и формирования
пользовательских лент.

## Запуск

Для хранения данных используется PostgreSQL, запущенный в Docker:

``` bash
docker run -d --name content-postgres -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=content_db -p 5434:5432 -v content_pgdata:/var/lib/postgresql/data --restart unless-stopped postgres:16
```

Основной класс `ContentserviceApplication` запускает сервис.

При запуске приложения Flyway автоматически выполняет неприменённые
миграции из `src/main/resources/db/migration`.

Миграция создаёт таблицы `messages`, `subscriptions` и необходимые
индексы.

Для получения данных о пользователях и проверки их ролей используется
`user-service`, доступный по адресу `http://localhost:9000`.

Доступ к сервису --- `http://localhost:9001`.

## Эндпоинты

### Лента

-   `GET /feed` --- Получить ленту сообщений пользователей, на которых
    подписан текущий пользователь.

### Сообщения

-   `POST /messages` --- Создать новое сообщение.
-   `GET /messages/{id}` --- Получить сообщение по ID.
-   `GET /messages?authorId=...` --- Получить список сообщений
    конкретного пользователя.
-   `DELETE /messages/{id}` --- Удалить сообщение.

### Подписки

-   `POST /subscriptions` --- Подписаться на пользователя.
-   `DELETE /subscriptions/{followingId}` --- Отписаться от
    пользователя.
-   `GET /subscriptions/{userId}/followers` --- Получить список
    подписчиков пользователя.
-   `GET /subscriptions/{userId}/following` --- Получить список
    пользователей, на которых подписан пользователь.

## Особенности

1.  Для аутентификации используется JWT, полученный от `user-service`.
    Подпись токена проверяется локально с использованием общего
    секретного ключа.
2.  Для обычных GET-запросов используются роли, содержащиеся в JWT.
3.  Перед выполнением операций создания и удаления сообщений, а также
    управления подписками сервис запрашивает актуальные роли
    пользователя у `user-service`.
4.  Выдача и отзыв ролей применяются без повторного входа пользователя и
    получения нового JWT.
5.  Если `user-service` недоступен во время проверки прав на изменение
    данных, операция запрещается.
6.  Поддерживаются четыре роли:
    -   `guest` --- просмотр ленты, сообщений и профилей, редактирование
        собственного профиля.
    -   `producer` --- права guest, а также создание и удаление
        собственных сообщений.
    -   `subscriber` --- права guest, а также подписка на пользователей
        и отписка от них.
    -   `administrator` --- полный доступ, включая удаление любых
        сообщений.
7.  Роли `producer` и `subscriber` независимы друг от друга.
    Пользователь может иметь обе роли одновременно.
8.  Пользователь с ролью `producer` может удалять только собственные
    сообщения. Администратор может удалять любые сообщения.
9.  Подписка на самого себя запрещена. Для подписки пользователь должен
    существовать.
10. Для идентификации пользователей, сообщений и подписок используется
    UUID.
